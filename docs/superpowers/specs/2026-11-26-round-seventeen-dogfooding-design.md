# 第十七轮 dogfooding 修复设计

## 意图

修复外部测试反馈 #81、#82、#84，优先保证用户无法因正文/归档内容而意外重复分配 issue 编号，同时恢复 `rename` 修复漂移的能力，并改善批量 JSON 读取性能。

## 目标

- `rename` 只有在索引摘要、正文标题、同号归档标题都无需变化时才是 no-op；已有漂移可由一次 rename 修复。
- `正文` 和 `附录` 仍是自由格式，不把其中的表纳入 issue 行解析；但可见且符合既有引用行判定的编号进入 `cited`，供取号、显式编号拒绝及 `citedRows` 使用。
- `list --json --with-body` 对大台账建立一次性查找索引，保持 JSON 内容和单次解析行为。
- 规范 fixtures 与三份真实台账的检查结果保持不变。

## 非目标

- 不把 `正文`/`附录` 中的表迁移或重写为正式 issue 表。
- 不增加通用 Markdown 表格解析器，不改变注释表、受控块或既有 W225 判定范围。
- 不改写 IO 写入、锁、快照协议，不引入依赖。

## 方案与取舍

### #81 rename

A. 仅比较表格摘要后早退：会让正文/归档漂移无法通过 rename 修复，拒绝。

B. 构建候选内容并让共享写入门禁判定字节是否变化：覆盖三份副本，仍由当前写入门禁负责 no-op；但须确保同摘要时跳过重复摘要检查且不规范化已一致的转义标题。采用此方案。

### #84 正文/附录编号

A. 在 close --keep-body 时遇表拒绝：保护编号但在最后一步阻止已有合法正文归档。

B. body/new 写入时拒绝表：修改正文编辑自由度，且无法覆盖 adopt 或既有内容。

C. 保持自由格式，只为编号安全扫描其中符合既有引用规则的表格行并记为 cited：表格仍不成为正式 issue，不产生 W225；增加引用来源与取号保护。采用此方案。

正文/附录中，仅可见、非注释、具有真实分隔行且带可识别编号列的表参与扫描；`ID | 状态 | 说明` 一类无摘要列的行，仅 ledger 状态词对应的行占号，与既有外来表规则一致。`怎么用`、`状态口径` 的受控表不受影响。

### #82 批量读取

预建 id 到行、正文 id 到块、以及独立占号索引，供单次 `list --with-body` 的各项复用。保持 exact body 优先、range/comma sibling fallback、重叠行不得借正文的现有语义。复杂性增加应限制在纯读取 helper 内。

## 约束与验证

- TypeScript/Bun 测试；不新增依赖。
- 遵循仓库 TDD、`npm run typecheck && npm test`；改动合入本地 main 后 `npm run build`。
- 用 `fixtures/canonical-clean.md`、`fixtures/cafe-shaped.md`、`fixtures/orca-shaped.md` 及真实 dogfooding 台账核对行为；不改外部测试台账。
- 不 push、不发布 npm 包。
