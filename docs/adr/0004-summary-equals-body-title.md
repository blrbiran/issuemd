# 摘要与正文标题存同一字符串，显示时截断

索引表的摘要列与正文 `### Issue N:` 的标题是同一个字符串（trim + 压缩空白后逐字相等）；`rename` 一次事务改两处；读命令按显示宽度截断，截断只发生在渲染时，不落盘。

**Why this is not obvious**: cafe 的实测数据显示「索引摘要 ≠ 正文标题」有 15/15 条，v1 规格因此一度考虑放弃这条不变量，把索引列改名「标签」，承认二者本就不相等。

**But**: 那 15 条的差异来源是列语义混用——索引写短标签、正文写完整描述。混淆的是「进展 vs 描述」和「标签 vs 标题」两件事。真正该消灭的是把进展写进表格（W260），而不是让两处存不同长度的标题。orca 两处存同一份，0/16 不一致。

**Consequences**

索引单元格会变长（orca 最长的开放标题约 150 字符）；GitHub 与编辑器会自动换行，`list` 在 80 字符处截断并加省略号。I3 保持 error 级，因此 `sync --titles` 有明确方向（`--prefer=body` 为默认），且不需要「索引摘要可为空表示同正文」这类例外。
