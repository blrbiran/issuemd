# 只有一种格式，不做兼容层

旧台账不通过运行时兼容层读写，也不提供 `migrate --to canonical`。`check` 只接受一种布局；旧台账由 agent 借 `adopt` 做一次性转写，转写后不再保留旧格式代码路径。

**Considered options**

- *canonical + 原地兼容 L1/L2*（v1 规格的路线）：`check` 需要两套相反的「索引 ↔ 已关闭」语义（L1 要求两表完全相等，L2 要求不相交），`counts --fix` 要能重写标题计数，`migrate` 要保证进度文字无损搬运。这些分支的维护成本高于它们服务的迁移窗口。
- *只支持 canonical，不做转写工具*：2600 行以上的手写台账交给 agent 逐行改写，不可复现且容易漏。

**Consequences**

`check` 从 19 条规则收到 17 条，全部为单一语义；E104 只剩「两表相交」一种判据；W230（计数与编号数不符）与 `counts --fix` 消失。代价是迁移是一次性的、diff 很大、只能靠 git 留底，且迁移期间的语义判断由人和 agent 承担。`adopt` 因此被限定为「只做机械改动 + 输出待决清单」，不替作者做语义决定。
