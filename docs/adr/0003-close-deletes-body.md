# 关闭即删正文，判据提升进表

`close` 会删除该 issue 的正文块，只把它 `**验收判据**` 段的内容提升到已关闭表的判据列。已关闭项在 `## 正文` 区出现即为 error（E111）。

**Why this is not obvious**: 直觉上保留正文信息更多，且 cafe 台账的成文协议正是「只改状态总览那一行；正文不动」。

**实测依据**：cafe 照自己的协议执行，已从 2663 行长到 2701 行，堆积了 13 条已关闭 issue 的正文；索引中 `已修` 从 48 涨到 61。orca 的协议相反（`check-issues.mjs` 的报错文案是 `closed? delete the block`），它的 16 条开放项正文标题与索引摘要 **0/16** 不一致。两份台账在关闭语义上互为反例，取 orca 方向。

**Consequences**

判据在任何时刻只有一份：开放时在正文，关闭后在表。`reopen` 只能从判据反推骨架，原描述不可逆丢失——这是被接受的代价，逃生口是 `close --keep-body`，它把正文归档到 `## 附录` 下的普通小节并报 W250——标题写成 `### #N <摘要>（已关闭，正文保留）` 而不是 `### Issue N:`，因为附录内出现 Issue 标题本身就是 E123。正文区长度因此有上界（等于开放项数量），已关闭表虽然很长，但只是判据仓库。
